## 四、前端 RBAC 实施计划（第 4-5 轮，分模块进行）

利用 Chrome DevTools 多角色登录验证，可以确保每个模块的按钮级权限正确。

### 第 4 轮: 基础设施

| Step | 文件 | 改动 |
|------|------|------|
| 4.1 | `src/router/index.ts` | 加 beforeEach 路由守卫：无 token → /login |
| 4.2 | `src/utils/auth.ts` | 加 parseToken() + getRoles() + getPermissions() |
| 4.3 | `src/App.vue` | 侧边栏根据 roles 过滤（admin 全显 / viewer 仅仪表盘+需求 / ...）|
| 4.4 | `src/store/user.ts` | 加 permissions state, setPermissions action |
| 4.5 | `src/directives/permission.ts` | 注册 v-permission 全局指令 |

### 第 5 轮: 逐模块加 v-permission（Chrome 验证每个模块）

| 批次 | 模块 | 视图数 | Chrome 验证内容 |
|------|------|--------|----------------|
| 5a | 仪表盘 + 需求管理 | ~8 视图 | admin 能看到"新建需求"，viewer 看不到 |
| 5b | 追溯 + 变更管理 | ~10 视图 | PM 能看到"创建变更"，RE 看不到 |
| 5c | 合规 + 电子签名 | ~13 视图 | COMPLIANCE 能看到审计日志，PM 看不到 |
| 5d | 风险管理 + 项目管理 | ~14 视图 | RISK_MGR 能看到"风险评估"，RE 看不到 |
| 5e | 系统管理 + 报表 | ~5 视图 | **仅 ADMIN** 能看到系统管理菜单 |

**验证方法**:
1. Chrome 用 admin 登录 → 截图全部菜单 + 按钮
2. Chrome 用 viewer 登录 → 截图仅菜单项 + 按钮隐藏
3. 逐角色（qa_mgr/pm/re/reviewer/risk_mgr/compliance/pd）登录 → 截图关键页面
4. 对比 RBAC 矩阵，确认每个按钮状态正确
